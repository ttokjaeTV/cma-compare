# CMA 금리 변경 감시

매일 아침 8시(KST)에 주요 금리 페이지를 확인해, 수치가 바뀌면 **GitHub Issue로 알려주는** 워커입니다.

## 감지만 합니다. 표를 자동으로 고치지 않습니다.

의도적인 설계입니다.

증권사 안내 페이지 중에는 **오래된 값이 갱신되지 않은 채 남아 있는 곳**, **배너와 금리표가 서로 다른 곳**이 있습니다. 스크래핑이 "성공"해도 값이 틀릴 수 있다는 뜻입니다. 게다가 "연 2.65%, 단 1,000만원까지" 같은 **적용 조건은 기계가 읽어내지 못합니다.**

그래서 워커는 "뭔가 바뀌었다"까지만 알리고, 실제 표 갱신은 사람이 공식 고시를 확인한 뒤 실행합니다.

---

## 동작 방식

각 페이지에서 **금리로 보이는 수치(0.5~8.0 사이 소수)** 를 뽑아 집합으로 저장하고, 다음 실행과 비교합니다.
HTML 구조를 파싱하지 않으므로 마크업이 바뀌어도 잘 깨지지 않습니다.

한국은행 기준금리 페이지만 예외로 **문서 순서상 첫 값**(= 현재 기준금리)을 봅니다. 추이표라 과거 금리가 전부 실려 있어서, 집합으로 비교하면 과거에 나왔던 금리로 인상될 때 변화를 놓치기 때문입니다.

## Tier

`targets.json`의 `tier: 1`은 **바뀌면 전 증권사가 따라 움직이는 지표**입니다. 하나라도 변하면 이슈 제목에 🚨가 붙고, 그때가 전수 갱신 타이밍입니다.

## 감시 범위는 전체가 아닙니다

금리를 공지 게시글로만 알리는 곳, 자동 요청을 차단하는 곳, 수치를 스크립트로 그리는 곳은 자동 추적이 불가능해 제외했습니다.
**알림이 없어도 분기에 한 번은 전수 확인**이 필요합니다.

---

## 파일

| 파일 | 역할 |
|---|---|
| `targets.json` | 감시 대상 목록 |
| `check.mjs` | 수집·비교 (외부 패키지 없음, Node 20+) |
| `baseline.json` | 직전 수집값. 워크플로가 자동 커밋 |
| `report.md` | 마지막 실행 결과 |

## 로컬에서 돌려보기

```bash
node watch/check.mjs
```

## 오탐이 잦다면

`check.mjs`의 `fingerprint()`에서 금리로 인정하는 범위(현재 0.5~8.0)를 좁히거나, `targets.json`에서 해당 대상을 빼면 됩니다.
