# CMA 금리 변경 감시

매일 아침 8시(KST)에 주요 금리 페이지를 확인해, 수치가 바뀌면 **GitHub Issue로 알려주는** 워커입니다.

## 감지만 합니다. 표를 자동으로 고치지 않습니다.

의도적인 설계입니다.

증권사 안내 페이지 중에는 **오래된 값이 갱신되지 않은 채 남아 있는 곳**, **배너와 금리표가 서로 다른 곳**이 있습니다. 스크래핑이 "성공"해도 값이 틀릴 수 있다는 뜻입니다. 게다가 "연 2.65%, 단 1,000만원까지" 같은 **적용 조건은 기계가 읽어내지 못합니다.**

그래서 워커는 "뭔가 바뀌었다"까지만 알리고, 실제 표 갱신은 사람이 공식 고시를 확인한 뒤 실행합니다.
(파일럿으로 AI가 고친 안을 PR로 올려 주는 단계가 붙어 있지만, **자동 병합은 없습니다** — 아래 「AI 데이터 수정 PR」)

---

## 동작 방식

각 페이지에서 **금리로 보이는 수치(0.5~8.0 사이 소수)** 를 뽑아 집합으로 저장하고, 다음 실행과 비교합니다.
HTML 구조를 파싱하지 않으므로 마크업이 바뀌어도 잘 깨지지 않습니다.

한국은행 기준금리 페이지만 예외로 **문서 순서상 첫 값**(= 현재 기준금리)을 봅니다. 추이표라 과거 금리가 전부 실려 있어서, 집합으로 비교하면 과거에 나왔던 금리로 인상될 때 변화를 놓치기 때문입니다.

## Tier

`targets.json`의 `tier: 1`은 **바뀌면 전 증권사가 따라 움직이는 지표**입니다. 하나라도 변하면 이슈 제목에 🚨가 붙고, 그때가 전수 갱신 타이밍입니다.

## 감시 범위는 전체가 아닙니다

금리를 공지 게시글로만 알리는 곳, 자동 요청을 차단하는 곳, 수치를 스크립트로 그리는 곳은 자동 추적이 불가능해 제외했습니다.
**알림이 없어도 분기에 한 번은 전수 확인**이 필요합니다.

---

## AI 데이터 수정 PR (파일럿)

변경이 감지되면 이슈 생성 뒤에 `ai-update.mjs` 가 한 번 더 돕니다.

1. 변경된 페이지 본문과 계산기(`index.html`)의 현재 값을 Claude에 보내, 새 금리·조건·적용일·**근거 문장(원문 그대로)**·신뢰도를 JSON으로 받습니다. 대상 한 곳당 호출 1번, 본문은 금리 숫자 주변만 약 8천 자로 줄여 보냅니다.
2. 코드가 AI 답을 다시 검사합니다 — 근거 문장이 페이지 본문에 **글자 그대로** 있는지, 그 문장에 새 금리 숫자가 들어 있는지, 기본 금리(조건부·우대 아님)인지.
3. 통과한 것만 `index.html` 의 `rp`/`bill` 의 `r`(금리)·`d`(적용일) 두 값을 고쳐 `ai/cma-YYYYMMDD` 브랜치로 **PR**을 만듭니다. PR 본문에 항목별 이전→이후, 근거 문장, 출처 URL, 그날 이슈 번호가 들어갑니다.

**고치지 않고 이슈에 `AI 추출 보류: 이유` 댓글만 남기는 경우**: 신뢰도 낮음 · 응답 파싱 실패 · 근거 문장이 본문에 없음 · 금리 0% 이하 또는 10% 초과 · 기존 값 대비 ±2%p 초과 변동 · 조건부/우대 금리로 보임 · 새 적용일이 기존보다 과거.

**자동으로 고치지 않는 것**: MMW 순수익률, note·요약 문구, 상단 「데이터 확인 기준일」 배지, README 기준일 표, 기준금리·증권금융 고시 같은 지표(전수 갱신 대상), 종금형. PR 체크리스트로 사람이 확인합니다. 페이지에 적용일이 없으면 `d` 에 확인일을 넣고 PR 에 경고를 표시합니다.

**병합은 항상 사람이 합니다.** PR 의 출처를 직접 열어 금리·적용일을 확인한 뒤 병합하세요.

### 켜려면 (운영자가 한 번만)

1. [Anthropic Console](https://console.anthropic.com) 에서 API 키를 만든다 (월 크레딧 한도 안에서 쓰도록 설정 권장).
2. 저장소 Settings > Secrets and variables > Actions > **New repository secret** — 이름 `ANTHROPIC_API_KEY`, 값에 키.
3. 저장소 Settings > Actions > General > Workflow permissions 에서 **「Allow GitHub Actions to create and approve pull requests」** 를 켠다. 꺼져 있으면 브랜치는 올라가지만 PR 생성이 거부되어, 이슈에 그 사실을 알리는 댓글이 달립니다.
4. 시크릿이 없으면 이 단계는 조용히 건너뜁니다 (기존 이슈 생성·기준값 갱신에는 영향이 없습니다).

비용은 호출 1번에 입력 약 1.5~6천 토큰·출력 약 0.3천 토큰(Sonnet급)이라 한 번에 몇 센트 이하이고, 변경이 있는 날만 대상 수만큼 호출합니다. 모델은 `ai-update.mjs` 맨 위 `MODEL` 상수 한 줄로 바꿉니다.

## 파일

| 파일 | 역할 |
|---|---|
| `targets.json` | 감시 대상 목록 |
| `check.mjs` | 수집·비교 (외부 패키지 없음, Node 20+) |
| `ai-update.mjs` | 변경 감지 시 AI 데이터 수정 PR (외부 패키지 없음, Node 20+ 내장 fetch) |
| `baseline.json` | 직전 수집값. 워크플로가 자동 커밋 |
| `report.md` | 마지막 실행 결과 |
| `changed-pages.json` | 변경된 페이지 본문 (AI 단계 입력. git 제외, 실행마다 덮어씀) |
| `test/` | AI 단계 시험용 가짜 응답·페이지·샘플 데이터와 `run.mjs` |

## 로컬에서 돌려보기

```bash
node watch/check.mjs
node watch/test/run.mjs     # AI 단계 시험 (가짜 응답, 키·네트워크 불필요)
node watch/ai-update.mjs --dry-run --mock watch/test/mock.json \
  --pages watch/test/pages.json --index watch/test/index.sample.html --out /tmp/out
```

`--dry-run`/`--mock` 은 API·git·gh 를 쓰지 않습니다.

## 오탐이 잦다면

`check.mjs`의 `fingerprint()`에서 금리로 인정하는 범위(현재 0.5~8.0)를 좁히거나, `targets.json`에서 해당 대상을 빼면 됩니다.
